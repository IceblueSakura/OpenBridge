# Responses v2: stateless text admission

This is the ownership and admission map for the **currently implemented offline v2 subset**, not the ceiling of the [Responses-first IR design](semantic-ir.md). The [refreshed standard baseline](../references/responses-standard.md) and [known conformance gaps](migration.md#当前已知闭合缺口) distinguish the larger target from current behavior. It is not the production Router contract or a promise that every Public Model supports these options. Exact accepted wire shapes and limits are enforced by `src/protocol/openai/`, `src/semantic/task/generation/`, and the independent fixtures under `tests/support/responses_profile.rs`. The [active focus](../implementation-plans/current-focus.md) owns remaining acceptance work. Transformation/failure rules below are required acceptance behavior, not a claim that every negative case already passes; concrete violations are tracked in the migration gap list.

| Domain | Authoritative owner | Wire admission and normalization | Transformation / failure rule |
|---|---|---|---|
| `instructions`, ordered text messages, string `input` | Task `GenerationSettings` / ordered `Item` + stable parts | String input becomes one user text item; absent, null, empty instruction and multi-part developer/system instructions stay distinct where admitted | Final task values encode the request; deleted items and part-bound breakpoints do not reappear |
| Function/custom tools, choice, calls, output | Task definition/policy and ordered call/result `Item` | Tool result may be text or text-part array; SDK-derived `parsed_arguments` must equal JSON parsed from authoritative `arguments`, and is not emitted | Call IDs and kind are checked; wrong association or unrepresentable Chat projection fails |
| Reasoning control, readable text, replay | Task policy / `ReasoningItem` / origin-bound fidelity record | Missing/null/empty controls are not interchangeable; readable text has reasoning delta/done, not message content-part events | Replay requires matching trusted origin and surviving owner; partial token cannot serve a subsequent request |
| `text.format`, verbosity, sampling and output limits | Task output constraint and generation controls | Text, JSON object and bounded JSON Schema have distinct typed controls; unknown controls fail | Re-derived requirements and target lowering must reflect final IR; inner schema is currently bounded JSON, with dialect/ordering validation still incomplete |
| Text, refusal, citation and token probabilities | Typed response part and event reducer | Static `output_text.logprobs` requires full reported details; delta probabilities may omit details that a matching final snapshot supplies | Replacement drops old annotations/probabilities; snapshot conflicts, invalid ranges and unknown metadata fail |
| Reported usage and terminal | Task response/event terminal | Absent usage stays absent; reported cached, cache-write and reasoning tokens are separate optional counters. Complete HTTP envelopes require SDK-readable details when usage exists | Never estimate missing counters; Responses-only cache-write details cannot silently project to Chat; incomplete/error cannot become success |
| Response and item IDs, timestamps, settings echo | Bounded representation and `ResponseContext` | Complete HTTP envelope requires reported settings and identity; low-level task snapshots may omit them | No guessed settings, timestamp or item identity; fidelity follows surviving owners only |
| Public model, state, service/cache/safety metadata | Request `RequestContext` / execution hints, **not Task IR** | Public model is fixed outside codec; `store` is emitted false. Only inactive server-side state forms are admitted | Non-inactive state, prompt templates, moderation and compaction fail before any Provider request |
| `stream`, stream options, HTTP and SSE | Delivery context and bounded transport framer | HTTP 200 + `text/event-stream`; BOM, LF/CRLF/CR and UTF-8 fragment handling; obfuscation is explicit | Bytes, events and aggregate semantic state have independent limits; malformed frames, wrong event type, missing delimiter/terminal and post-terminal events fail closed |

`SseLimits::max_obfuscation_bytes` independently bounds aggregate decoded UTF-8 padding across the stream (default 4 MiB). Zero permits unpadded streams but rejects nonempty padding. Decoder charging is per framed payload, independent of input fragmentation; encoder charging happens before padding allocation. Exhaustion poisons the stream rather than silently disabling requested obfuscation. Single-event and total-wire limits still apply, including escaped JSON overhead. Seeded test padding proves neither production entropy nor a side-channel guarantee.

The independent tests `semantic_v2_text_profile`, `semantic_v2_responses_sse`, `semantic_v2_body_lifecycle` and the explicitly ignored `semantic_v2_responses_sdk_loopback` cover distinct layers. Codec and SDK loopback checks are not production wiring evidence. Media, hosted tools, server-side conversation/background and real Provider execution are outside this admission. The remaining full field/event negative-case audit must be completed before clearing the active focus. Production execution is a later phase, not a completion condition for this offline slice; the predecessor runtime is [archived](../archive.md).
