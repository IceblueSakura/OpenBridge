# ADR-0002：多任务 IR 类型族与语义所有权

## 状态

- **决策：已接受，待按任务实施。** 先核查任务表达与语义所有权，再迁移 codec，并以离线、Provider 无关的测试验收。
- **关系：补充并收窄 [ADR-0001](0001-generation-ir-authority.md) 的任务边界与目标执行顺序。** 保留其 IR 权威、保真和失败原则；不把所有使用 Chat wire 的任务都解释为对话 Generation。
- **实现：尚未形成完整类型族。** 当前只有 Generation Static/Event IR；Embedding、Images 仍使用结构事实与保留 body。具体缺口由[实施状态](../implementation-status/current-boundaries.md)维护。

## 背景与问题

协议、任务与模态是不同维度。Chat wire 可以承载普通对话、ASR 或 TTS；音频可能是待理解内容，也可能是音色条件。仅按 endpoint decode 会误解用途；仅保留原 JSON 又不能让 IR 成为后续分析和变换的权威。

类型存在、codec 完整映射和生产路径使用必须分别成立。逐字段替换 Native 输出以前，需要证明 IR 足以区分支持范围内的语义，并能表达对应响应；请求能编码不等于响应能解码。

## 决策

### 1. 按任务划分 IR，共享有界基础值

采用任务类型族，不建立带大量可选字段的万能请求结构，也不复制第二套 Generation IR。

| 任务族 | 必须拥有的语义 | 不得混入 |
|---|---|---|
| Generation | 有序会话与指令、工具及结果、reasoning/refusal、生成控制、输出约束、候选和引用 | 向量批处理、专用语音任务的隐式解释 |
| Embedding | 文本或 token-ID 输入、批次与结果索引、请求维度、向量数值及表示契约 | 对话角色、工具、生成终态 |
| Image Generation | 提示与已支持的生成选项、输出数量/尺寸、图片结果与使用量 | 通用会话历史、尚未开放的编辑/视频任务 |
| Speech | 识别、合成、音色设计和克隆的明确任务变体；目标文本、语言、声音条件与输出格式 | 把参考音频当作待转写内容，把 TTS 目标文本当作历史回答 |

共享有界文本/二进制、媒体资源、稳定身份、受限扩展及保真结果；共同值不能抹平各任务的不变量。Generation 的音频理解仍是多模态 Generation，不因含音频就改成 Speech。外层需要统一调度时使用有标签的任务联合；具体 Rust 类型名和模块迁移由实施切片确定。

Models、健康检查、认证和本地 MCP 不伪装成模型推理 IR。定义任务类型族不扩大任何现有 endpoint、模型能力或路由支持。

### 2. 先识别任务，再语义 decode，最后选择 Provider

```text
下游 wire
  → admission：认证、有界严格解析、endpoint 与 Public Model 标识
  → 解析 Public Model 的固定任务契约（不选择 Provider）
  → 按任务和下游协议 decode
  → 任务 Request IR + 受约束的 wire 保留元数据
  → 语义校验 / 未来受信处理位置
  → 从最终 IR 提取 requirements，执行固定接口预检
  → 既定 Route 计划
  → 每个候选独立投影、可表达性检查与 encode
  → 受信 transport

上游结果
  → 按已选任务和上游协议 decode
  → 任务 Response IR / 适用的 Event IR
  → 校验 / 未来受信响应处理位置
  → 下游协议 encode
  → commit 与 body lifecycle
```

任务解析只消费受信 Public Model 契约；纯 codec 不查询 registry，不获得凭据或 endpoint。未知模型、任务与 endpoint 不匹配时，在语义执行前拒绝，不根据输入内容猜测或改选任务。

未来 IR 变换后重新验证身份、资源和能力要求，不能继续使用旧 requirements。候选投影从同一不可变 IR 独立生成；已有允许的参数省略规则仍按目标应用，不污染重试或后续候选。不可表达不等于可跳过较弱 Route，固定候选顺序与交集规则不变。

### 3. 每类信息只有一个输出 owner

| 分类 | 所有权与处理 |
|---|---|
| 已建模语义 | IR 唯一决定值及删除；encoder 不得从源字段恢复已删除内容 |
| 表示元数据 | 只保留语义等价的拼写、顺序或 envelope 表现；有明确挂载位置和合并规则，不得覆盖语义 |
| 来源限定扩展 | 有大小、命名空间、来源、暴露策略与目标允许范围；未知来源不获得跨 Provider 重放权限 |
| 不可表达内容 | 明确拒绝；只有已批准、可追踪的降级策略才允许省略 |

保留元数据应绑定稳定 item/call/part 身份，不靠变换前的数组下标合并。删除 item 同时移除其附属元数据；新 item 不继承不相关的源字段。当前受支持的核心语义不能长期藏在 opaque 扩展或整段原 JSON 中。

省略、`null`、空字符串、空列表、显式默认值和显式关闭分别解释。只有来源与目标契约能证明等价时才可折叠；例如 `strict` 省略与 `false` 不得不加区分地跨协议重放。保留必要的语义 presence，而不是机械地把所有字段包装成同一种可空类型。

### 4. 媒体与事件必须保持可解释性

- 资源区分 URL、inline bytes 和来源绑定引用；在任务需要时保留 MIME/容器/编码、文件名、图片 detail 及资源用途。不主动下载 URL 或转码。
- 音频内容理解、识别输入、合成输出与音色条件由任务明确解释。输出格式、voice、语言，以及适用的 PCM 参数不能只存在于源 JSON。
- 流式媒体需有与任务对应的 typed event，保留 item/part 身份、顺序、格式及增量边界；不以通用 opaque 事件代替已支持的媒体语义。
- Static/Event IR 对同一支持语义应有一致的终态表达；空输出、refusal、部分结果、失败与取消不能被归一为成功。候选数量与工具结果关联在请求、响应和事件层闭合。
- 事件逐步 decode/encode，不要求聚合整条流；每事件、每资源和累计预算分别有界，取消与下游背压继续传递。提交后失败不能重试拼流或补造成功 terminal。

### 5. Embedding 有独立数值与身份契约

保留文本与 token-ID 输入、单项/批次形状、输入顺序及完整 index 对应。Token ID 依赖 tokenizer/input encoding，不能仅因数值数组相同就跨任务或模型解释。

向量数值与 wire encoding 分开表达：普通 JSON 数值不得无条件压为 `f32`；只有固定 profile 明确允许时才做 little-endian float32/Base64 表示转换，并声明其精度边界。统一检查维度、批次、索引、有限值、字节长度与分配上限；不得借编码转换归一化、降维或改变 vector identity。

模型/向量空间的等价性由受信执行契约判断，IR 不携带 credential 或可选择上游的定位信息。引入 Embedding IR 不解除当前跨模型 fallback 禁止。

### 6. 设计准入先于语料扩张

每个待迁移任务先给出“支持语义 → IR 所有者 → 双向 codec → 失败结果”的对应关系。以下条件满足后，才把新语料纳入该任务的正式验收：

1. 支持范围内有意义的差异在 IR 中可区分，或有明确等价规则；无未解释的源 JSON 依赖。
2. 请求与对应响应闭合，Static/Event 一致，资源与失败边界可执行。
3. 语义、表示元数据和扩展的合并/删除规则明确；变换后校验与候选隔离成立。
4. 独立 expected 能分别验证 decode 和 encode，不以 round-trip 自证完整性。

语料预筛与小型反例可以服务设计核查，但不表示设计已经通过。Provider 无关指测试不依赖账号、真实模型或上游网络，并非抹去被测试的协议/profile。具体离线测试方法由 [semantic testing](../../testdata/semantic-testing.md)维护。

## 替代方案与理由

| 方案 | 结论 |
|---|---|
| 所有任务复用 GenerationRequest | 拒绝；会话、向量与语音条件的不变量不同，易产生非法组合 |
| 只按 wire 协议分 IR | 拒绝；相同 Chat 字段在不同任务中含义不同，妨碍安全变换 |
| 每个 Provider 自建完整内部模型 | 拒绝；重复语义规则，跨源处理与 hook 再次分裂 |
| 任务 IR 类型族 + 共享基础值 + 受限保留元数据 | 采用；增加显式映射工作，但任务合法性和语义所有权可分别验证 |

## 影响与落实

先收敛任务边界与支持语义表，再补齐当前类型/codec 缺口；不得用全量重写、降低 Native 能力或扩大公开支持面换取形式统一。当前请求/响应映射差距归[实施状态](../implementation-status/current-boundaries.md)，推进次序归[下一步目标](../implementation-plans/next-goal.md)。本 ADR 不固定代码接口、不引入 hook 框架，也不承诺未开放的 Realtime、视频、状态服务或任意跨源转换。
