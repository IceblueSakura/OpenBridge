# 后续计划

## 当前主线

本阶段保持 **Agent-first，优先完善规范 Responses 路径**。文件仅维持既有 user inline/URL 基础输入及必要正确性、安全维护；其余文件功能暂停，不作为下一片或其他模态的前置；恢复评估节点见下文推进顺序，不以所有模态完成为条件。Gateway 与未来 Agent 复用一套独立 Semantic Model / IR；Chat Completions 只作为允许有限语义损失的兼容路径，不用它的表达力限制共享核心。

用户允许迁移采用大范围破坏性重写，不要求保留旧 API、旧类型或兼容垫片；实施仍按有独立验证边界的切片推进，不把方法许可理解为无关全库重写、生产变更或任意数据丢弃。总体合同归 [Semantic Model](../architecture-v2/semantic-ir.md)，当前获准行为归 [current-focus](current-focus.md)。

- 迁移不恢复独立 `_openbridge` carrier，不保留隐式兼容入口或同义私有字段。重建与否、重建范围在迁移完成后重新决定；当前边界归[客户端合同](../architecture-v2/client-generation-profile.md)。
- Chat 默认采用逐条定稿、独立验证的有限有损规则，不要求每个请求另加开关。必要行为约束、工具/replay 依赖和真实终态仍受保护；允许损失不等于当前代码已经实现所有规则。
- Audio Realtime 是明确要实现的后续目标；为降低每阶段关注度，本阶段不展开实时协议、状态机或音频重构。
- 独立 TTS、转录、图片生成等功能可采用额外 OpenAI 标准 operation；具体端点、首批能力及资源服务范围仍需深入讨论，不能把方向许可当作全量接入授权。
- Embedding 保持同一语义体系内的独立 task 与标准 `/v1/embeddings` 目标，但不作为本阶段 Text/Image/File 闭合的前置。
- Gemini/Anthropic 原生协议接入与 Agent runtime 后置；不提前构造工具执行、记忆、会话管理或通用工作流框架。

## 推进顺序与退出条件

按场景完成纵向闭环，不先批量扩展模态、再集中补标准接口或 Agent 消费。当前图片方向维持 `/v1/images/generations` 的基础静态生成与有序产物集合，优先保持控制、严格交付、预算和失败边界的正确性；SSE、流式预览/最终产物事件、编辑、蒙版、参考图、URL 产物下载及文件服务均延期，不作为当前收口前置。恢复这些功能或追加其他图像生成模型验证时另行选片，不自动扩大实现与测试集合。文件扩展仍延期，选片前按下述节点重评。每片保持既有文本、图片与基础文件输入的正确性和拒绝边界，只解决该场景实际依赖的缺口，不等待全部既有缺口闭合。

| 片内顺序 | 工作 | 退出条件 |
|---|---|---|
| **1. 选定最小场景** | 明确标准 operation、输入输出、必要回传、非目标与独立预期，不推进文件扩展 | 范围有限；可观察结果、失败例、不变量和验证边界写入 current-focus。文件 ID/产物/服务不构成退出条件 |
| **2. 验证语义与类型化消费** | 用最小反例确定 task、modality、resource 的 owner；同步用纯库消费者直接构造、检查和编辑交互 | 独立模型不依赖协议 DTO、私有 wire 或网络；消费者与标准接口共用语义权威及验证规则。必要结构选择有迁移方案；有回传需求时验证依赖保留或失效，有跨请求保存需求时另定版本与完整性，不把内存 fingerprint 当持久化协议 |
| **3. 贯通标准接口与交付** | 完成标准入口→IR→目标→交付→必要回传，覆盖请求/history、输出及适用事件，并收敛该场景涉及的本地兼容形式 | 固定标准/schema/SDK 的独立预期、编辑、预算与失败检查通过；标准场景不依赖私有字段，不以 SDK 宽松解析冒充符合性；静态与适用事件语义一致 |
| **4. 完成必要 Chat 兼容与回归** | 对该场景制定必要的具名投影规则或明确拒绝，说明方向、前提、损失观察与消费者后果；不建立第二语义模型 | 静态/事件一致；核心值不被投影污染；明确断言允许损失与受保护不变量。`phase` 等可能影响后继行为的信息不因 optional 就归为安全损失 |
| **5. 评估下一片** | 依据已闭合场景暴露的真实缺口和消费需求选择后续场景 | 不自动扩大到整类模态，不以预建框架替代具体需求 |

第 2～4 项属于同一切片的设计、实现与验收，不是全项目阶段门；类型化消费检验从首片起必需，必要 Chat 回归随片保留，不要求实现 Agent runtime。属于 Responses 的场景在片内完成 Responses 闭环；独立媒体场景完成其已定稿的标准 operation，不强塞进 Responses，也不以非文件模态全部完成作为 Responses 完善的前置。

文件扩展继续暂停，重评节点为当前静态生成控制切片闭合后的下一次选片，不以真实模型注册、binary 激活或付费验证为前置。届时评估是否继续延期；更多图片能力、其他模态与 Realtime 不自动推迟节点。重评不自动恢复文件实施，也不要求所有模态或所有 operation 完成。不为基础文件输入补建完整资源服务，也不以延期为由将已有语义缺口藏进 adapter/fidelity。

## 下一片需要解决的结构问题

1. **其他模态的最小场景**：分别确定 task、modality、resource 与标准 operation 的 owner 和验收边界；不以扩充文件来源或文件服务作为前置。文件 issuer-bound 引用、工具文件结果、生成文件产物、更多文件格式/目标、Chat 文件投影及文件管理 API 均延期，保留缺口与现行拒绝。
2. **Agent-first 交互**：保留工具 call/result、指令 authority、原始参数和必要 replay 的权威；区分响应闭合、逻辑 turn 进度和续轮要求。不以移除 carrier 为由删除共享语义或推断邻接关系。
3. **标准载体与兼容损失**：先用已固定官方合同确定 wire，而非让用户重复选择标准要求。真正的共享结构调整仍报告方案；Chat 规则不能反向放宽 Responses 或改造私有替代字段。

结构方向可以破坏性替换，但先按 [IR 缺口规则](../architecture-v2/semantic-ir.md#4-ir-不足与标准载体缺口)说明受影响 owner、合法状态、事件/依赖与迁移验证；具体 Rust 布局和局部算法属于工程决策，不逐字段制造审批门。

## 后续范围与验证

请求型音频、Embedding、独立媒体操作及 Realtime 分别选片，不与当前重写捆绑；文件扩展按上述有限范围的重评节点另行决定。Realtime 延后是明确的实施顺序，不是永久排除。Provider 原生缓存、计量、Schema、凭据和运行保障按当前场景的依赖维护，不作为扩张基础设施的理由。

实现先有独立失败预期，再覆盖 owning layer 与必要实际交付。变更类型、序列化、profile、OpenAPI、fixtures 与消费者一起更新，保持资源、取消、严格终态及提交后禁止前移。真实调用、部署与提交均需对应授权，运行结果不存入计划或长期能力矩阵。
