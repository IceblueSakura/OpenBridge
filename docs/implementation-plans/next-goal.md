# 下一步目标：闭合 Generation IR 语义管线

## 目标与状态

**方向已明确，代码实施尚未开始。** 依据 [ADR-0001](../decisions/0001-generation-ir-authority.md)，让 Generation 请求和响应的最终 wire 由富语义 IR 决定，为之后的分析、工具注入和拦截提供统一位置。

这不是要求每个请求都能跨 Provider 或跨协议，也不是本轮实现 hook。当前文档修订不改变运行时行为；具体获准实施切片另记于[当前开发焦点](current-focus.md)。

## 当前起点

已有 Static/Event IR、Chat/Responses codec、固定路由、Provider adapter 和有界响应生命周期。主要缺口是 Native 的源对象保留路径与 Provider JSON 变换尚未统一到 IR 语义权威之下。详见[当前实现](../implementation-status/current-state.md)，不新增平行 IR 或一次性推倒重写。

## 推进顺序

| 阶段 | 交付结果 | 关键验收 |
|---|---|---|
| 1. 明确语义所有权 | 梳理受支持语义、保留元数据、Provider 私有扩展与拒绝边界；确定现有 IR 缺口 | 每类字段有唯一输出 owner；没有以保真为名的无约束原始 JSON 旁路 |
| 2. 闭合同协议静态链路 | 请求与 JSON 响应均由 IR 驱动编码；请求 decode 与候选编码解耦 | 未修改时语义保真；修改后 wire 变化；删除不会被 source 恢复 |
| 3. 收敛路由与 Provider 编码 | IR 后执行既定预检与路由；每个候选应用明确的协议/Provider 编码规则 | 固定候选策略不变；不可表达请求在发送前失败；重试不累积上次编码修改 |
| 4. 统一响应与流式路径 | Response/Event IR 驱动下游输出，跨协议只投影可表达语义 | identity、工具增量、usage 与终态正确；有界内存、取消和 commit 约束不退化 |

这些阶段是依赖顺序，不是要求拆成固定数量的 PR。每个实施切片必须同时维护其受影响的 codec、调用方和合同，不能长期保留相互冲突的双路径。

## 验收原则

- **同协议保真**：保护已支持的普通内容、工具、reasoning、refusal、媒体与扩展语义，不以跨协议较窄子集裁剪 Native。
- **IR 修改有效**：测试分别覆盖新增、替换、删除；期望值独立于生产 encoder，避免自证。
- **转换边界明确**：精确保留、等价规范化、来源限定保留和拒绝各有明确结果，不静默丢失。
- **资源与失败安全**：覆盖超限、非法扩展、工具身份冲突、异常终态、取消和提交后失败。
- **验证适度**：优先最低 owning layer 的确定性测试，必要时补 production Router 场景；不扩成逐模型全排列验证。

具体命令见[开发指南](../development.md)。真实 Provider、SDK/Agent 与负载验证按具体变更另定；不以静态文档或 codec 单测声称外部兼容。

## 本目标不包含

- hook/plugin 系统、动态脚本、工具执行器、工具拦截续轮或分析策略实现；
- 动态能力路由、任意跨源 fallback、上游有状态能力；
- 把 Embeddings、Images、MCP 或管理接口并入 Generation IR；
- 逐模型能力扩张、生产部署或真实付费探测。

## 实施前需落定的局部设计

源保留元数据的存放形式、受支持字段的 IR 补齐顺序、Provider 映射接口，以及流式可变换事件的精确边界，应在对应切片结合源码与失败测试确定。这里不预先承诺类型名、插件 API 或未核实的完整支持矩阵。
