# 后续计划

## 当前主线

本阶段聚焦 **Agent-first 的 Text/Image/File 交互，优先完善规范 Responses 路径**。Gateway 与未来 Agent 复用一套独立 Semantic Model / IR；Chat Completions 只作为允许有限语义损失的兼容路径，不用它的表达力限制共享核心。

用户允许迁移采用大范围破坏性重写，不要求保留旧 API、旧类型或兼容垫片；实施仍按有独立验证边界的切片推进，不把方法许可理解为无关全库重写、生产变更或任意数据丢弃。总体合同归 [Semantic Model](../architecture-v2/semantic-ir.md)，当前获准行为归 [current-focus](current-focus.md)。

- 迁移不恢复独立 `_openbridge` carrier，不保留隐式兼容入口或同义私有字段。重建与否、重建范围在迁移完成后重新决定；当前边界归[客户端合同](../architecture-v2/client-generation-profile.md)。
- Chat 默认采用逐条定稿、独立验证的有限有损规则，不要求每个请求另加开关。必要行为约束、工具/replay 依赖和真实终态仍受保护；允许损失不等于当前代码已经实现所有规则。
- Audio Realtime 是明确要实现的后续目标；为降低每阶段关注度，本阶段不展开实时协议、状态机或音频重构。
- 独立 TTS、转录、图片生成等功能可采用额外 OpenAI 标准 operation；具体端点、首批能力及资源服务范围仍需深入讨论，不能把方向许可当作全量接入授权。
- Embedding 保持同一语义体系内的独立 task 与标准 `/v1/embeddings` 目标，但不作为本阶段 Text/Image/File 闭合的前置。
- Gemini/Anthropic 原生协议接入与 Agent runtime 后置；不提前构造工具执行、记忆、会话管理或通用工作流框架。

## 推进顺序与退出条件

| 顺序 | 切片方向 | 退出条件 |
|---|---|---|
| **1. Text/Image/File 承载与 Responses 边界** | 以标准文件输入、图片输入/工具结果和 Agent 续轮检验内容、来源、描述、identity 与依赖；逐项区分 IR 缺口、目标缺口和未接线 | 必要结构选择有最小反例和迁移方案；独立模型不依赖协议 DTO。文件 ID/URL/inline 的用途与信任边界清楚，不隐式下载上传或文本化 |
| **2. 标准 Responses 闭环** | 按有限场景完善请求/history、输出与适用事件，处理当前本地兼容形式；优先形成客户端→IR→目标→交付→必要回传路径 | 固定标准/schema/SDK 的独立预期、编辑、预算与失败检查通过；标准场景不依赖私有字段，不以 SDK 宽松解析冒充符合性 |
| **3. 必要 Chat 兼容投影** | 随已闭合场景制定具名损失规则，明确方向、前提、损失观察与消费者后果；不建立第二语义模型 | 静态/事件一致；核心值不被投影污染；明确断言允许损失与受保护不变量。`phase` 等可能影响后继行为的信息不因 optional 就归为安全损失 |
| **4. Agent 语义消费检验** | 用类型化消费者构造、编辑、检查上述交互，不强迫绕行 Responses JSON；按需求收敛公共类型 | 不双写语义权威，不依赖私有 wire 或网络；有保存/回传需求时另定版本和完整性，不把内存 fingerprint 当持久化协议 |

这些顺序不是全量阶段门：必要 Chat 回归随 Responses 切片保留，Agent 消费视角贯穿设计。无需先设计全部工具/replay 或完整多模态再实现文件输入；但已有语义缺口不能藏进 adapter/fidelity。

## 下一片需要解决的结构问题

1. **文件与媒体来源**：共享 URL/inline/引用基础值，文件名、媒体描述、输入用途与产物身份各有 owner；不能让图片特定字段/预算冒充通用资源合同。
2. **Agent-first 交互**：保留工具 call/result、指令 authority、原始参数和必要 replay 的权威；区分响应闭合、逻辑 turn 进度和续轮要求。不以移除 carrier 为由删除共享语义或推断邻接关系。
3. **标准载体与兼容损失**：先用已固定官方合同确定 wire，而非让用户重复选择标准要求。真正的共享结构调整仍报告方案；Chat 规则不能反向放宽 Responses 或改造私有替代字段。

结构方向可以破坏性替换，但先按 [IR 缺口规则](../architecture-v2/semantic-ir.md#4-ir-不足与标准载体缺口)说明受影响 owner、合法状态、事件/依赖与迁移验证；具体 Rust 布局和局部算法属于工程决策，不逐字段制造审批门。

## 后续范围与验证

请求型音频、Embedding、独立媒体操作及 Realtime 分别选片，不与当前重写捆绑。Realtime 延后是明确的实施顺序，不是永久排除。Provider 原生缓存、计量、Schema、凭据和运行保障按当前场景的依赖维护，不作为扩张基础设施的理由。

实现先有独立失败预期，再覆盖 owning layer 与必要实际交付。变更类型、序列化、profile、OpenAPI、fixtures 与消费者一起更新，保持资源、取消、严格终态及提交后禁止前移。真实调用、部署与提交均需对应授权，运行结果不存入计划或长期能力矩阵。
